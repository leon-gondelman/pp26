Block 2: the three parts

In a strict language a value is computed where it is written. In this block we put a function in its place.

1Thunks
when?		We choose when the value is computed: when we call the function.
2Sequences
how far?		We put the function inside a data structure. We choose how far a sequence is computed, and it can be without end.
3Memoisation
how many times?		We keep the result of the function. We choose that the value is computed at most once.
PART 1

Thunks

How does a strict language wait?

Session 4: if written as a function

let my_if c t e = if c then t else e

let rec fact n =
  my_if (n = 0) 1 (n * fact (n - 1))

fact 5 never returns. OCaml computes the two branches before it calls my_if.

let my_if c t e = if c then t () else e ()

let rec fact n =
  my_if (n = 0) (fun () -> 1)
    (fun () -> n * fact (n - 1))

fact 5 is 120. my_if calls one of the two functions.

A function that holds a computation and waits for its call is a thunk. In OCaml we write it fun () -> e.

A thunk, called twice

What does the program print, and in which order?

  • When the thunk is made, its body is not run.
  • At every call the body is run again.

The same program in OCaml

OCamllet t = fun () ->
  print_endline "computing";
  6 * 7

let () = print_endline "the thunk is made"
let a = t ()
let b = t ()
A thunk computes at every call. It is session 4's call-by-name, written by the program.

A left fold and a right fold: who holds the rest of the list?

let rec fold_left f acc xs =
  match xs with
  | [] -> acc
  | x :: xs -> fold_left f (f acc x) xs

Our function receives the accumulator and one element. The rest of the list, xs, stays with the fold.

let rec fold_right f xs z =
  match xs with
  | [] -> z
  | x :: xs -> f x (fold_right f xs z)

Our function receives one element and the fold of the rest, as its second argument.

Only with a right fold is our function given the rest, and can decide what becomes of it.

fold_right keeps one frame waiting per element; fold_left keeps none: its recursive call is a tail call.

Block 1's exists, with the left fold

OCamllet exists p l = fold_left (fun found x -> found || p x) false l

exists, with the right fold

OCamllet exists p l = fold_right (fun x rest -> p x || rest) l false

let rec fold_right f xs z = match xs with

Lazy evaluation, in Haskell

In Haskell no argument is computed before the call. It is computed when the function uses it, and at most once: session 4's call-by-need.

The two folds, on a list without end

Haskellfoldr (\x rest -> x > 2 || rest)
      False [0 ..]
True
foldr f False [0 ..]
= f 0 (foldr f False [1 ..])
= …
= f 3 (foldr f False [4 ..])
= True

The call on top is f, our function. At 3 it answers, and does not read its rest.

foldl (\found x -> found || x > 2)
      False [0 ..]
the program does not end
foldl f False [0 ..]
= foldl f (f False 0) [1 ..]
= foldl f (f (f False 0) 1) [2 ..]
= foldl f (f (f (f False 0) 1) 2) [3 ..]
= …

The call on top is always foldl: no step answers. The calls of f wait, and are never run.

Laziness delays what a function is given. In Haskell as in OCaml, only with the right fold is our function given the rest.
PART 2

Sequences

How do we postpone the next element?

From a list to a sequence

type 'a list =
  | []
  | (::) of 'a * 'a list

The rest of a list is a list: a value. It is computed before we read the first element.

type 'a node =
  | Nil
  | Cons of 'a * 'a seq

and 'a seq = unit -> 'a node

The rest of a sequence is a thunk. It is computed when we call it.

A sequence (also called a stream)* is a thunk that gives one element and the rest of the sequence.

* CS3110, section 9.4. OCaml's library has this type as Seq.t.

nats and take

OCamllet rec nats n : int seq =
  fun () -> Cons (n, nats (n + 1))

let rec take n (s : 'a seq) =
  if n = 0 then []
  else match s () with
    | Nil -> []
    | Cons (x, rest) ->
        x :: take (n - 1) rest

nats 0 is the sequence of all the natural numbers.

What does take 5 (nats 0) compute, and how many elements of nats 0?

[0; 1; 2; 3; 4]   produced=5
A sequence without end is a value: we can name it, pass it and keep it. Five of its elements are computed, because we ask for five.

A list and a sequence, drawn

After three calls, three cells are built. The rest, nats 3, is a thunk that nobody has called.

map and filter on a sequence

OCamllet rec map f (s : 'a seq) : 'b seq =
  fun () -> match s () with
    | Nil -> Nil
    | Cons (x, rest) ->
        Cons (f x, map f rest)

map f s returns at once: its body is under fun () ->.

let rec filter p (s : 'a seq) : 'a seq =
  fun () -> match s () with
    | Nil -> Nil
    | Cons (x, rest) ->
        if p x
        then Cons (x, filter p rest)
        else filter p rest ()

When x does not pass, filter asks for the next element itself.

In a Cons, the recursive call returns at once: it makes a function that nobody has called yet. The rest is computed when the consumer asks for it.

PART 3

Memoisation

Can a value be computed at most once?

A thunk and a lazy value, each asked twice

OCamllet ticks = ref 0

let t = fun () -> incr ticks; 6 * 7

let a = t ()
let b = t ()
a=42 b=42 ticks=2
let ticks = ref 0

let l = lazy (incr ticks; 6 * 7)

let a = Lazy.force l
let b = Lazy.force l
a=42 b=42 ticks=1

What is !ticks at the end of each program?

A thunk delays. A lazy value delays and remembers: it is session 4's call-by-need.

Okasaki 1998, chapter 4: a stream is part 2's sequence with a lazy value, not a thunk, for the rest.

A thunk and a lazy value, drawn

lazy, made by hand

OCamltype 'a state =
  | Delayed of (unit -> 'a)
  | Value of 'a

let delay f = ref (Delayed f)

let force s = match !s with
  | Value v -> v
  | Delayed f ->
      let v = f () in
      s := Value v;
      v

A lazy value is a reference that holds a thunk, and after the first force the value.

let s = delay (fun () ->
  incr ticks; 6 * 7)

let a = force s
let b = force s
a=42 b=42 ticks=1
With delay we write the fun () -> ourselves. lazy e is a keyword: a function would receive e already computed.
With a table in the place of the reference, we keep one result for each argument. This is the memoisation of a function: see the appendix.

The Fibonacci numbers, as a list without end

Haskellfibs = 0 : 1 : zipWith (+) fibs (tail fibs)
The list is read at two places, one cell apart, and their sum is its next cell. Each cell is computed once, and read twice.

Lab 2's queue, without memoisation

OCamllet pop = function
  | x :: front, rear ->
      Some (x, (front, rear))
  | [], rear ->
      match rev rear with
      | [] -> None
      | x :: front ->
          Some (x, (front, []))

Lab 2's queue, as we wrote it there: a front and a rear. When the front is empty, pop reverses the rear.

(* q: eight elements pushed *)

let b = pop q
a=1 b=1 reversals=2
The queue is persistent: q can be used twice. With this pop, the reversal is then paid twice.
With lazy the reversal is suspended inside q: the two pops share it, and it is paid once. We write that queue as homework, at the end of the warm-up's sheet.

APPENDIX · TO READ AT HOME

Memoising a function

Can a function remember what it has computed?

fib 25, without memoisation

OCamllet rec fib n =
  if n < 2 then n
  else fib (n - 1) + fib (n - 2)

let a = fib 25
let b = fib 25
a=75025 b=75025   the body ran 485570 times

The second call computes everything again: a function keeps nothing from one call to the next.

With lazy (fib 25) we keep one result, for the argument 25. Every other argument needs a lazy value of its own.

A lazy value keeps the result of one computation. To memoise a function is to keep a result for each argument: a table in the place of the reference.

memo: a function that keeps a table

OCamllet memo f =
  let table = Hashtbl.create 16 in
  fun x ->
    match Hashtbl.find_opt table x with
    | Some y -> y
    | None ->
        let y = f x in
        Hashtbl.add table x y;
        y

memo f makes a table, once, and returns a function.

  • Called on x, the function looks x up in the table.
  • If the result is there, it returns it, and f is not called.
  • If not, it calls f, keeps the result, and returns it.
The function returned is a closure with a state, as block 1's counter. lazy is the same with one entry: the table of a function of no argument.

memo fib: the calls that the table sees

OCamllet rec fib n =
  if n < 2 then n
  else fib (n - 1) + fib (n - 2)

let mfib = memo fib
resultthe body of fib ran
mfib 2575025242 785 times
mfib 25, again750250 times

The second call is answered from the table. The first one is as slow as fib 25.

Inside fib, the two recursive calls are calls of fib, not of mfib. The table sees only the calls that we make.

memo_rec: the function receives the function to call

let fib' self n =
  if n < 2 then n
  else self (n - 1) + self (n - 2)

fib' does not call itself: it has no rec. It calls self, which it receives.

memo_rec fib' 25 = 75025
the body ran 26 times
OCamllet memo_rec f =
  let table = Hashtbl.create 16 in
  let rec g x =
    match Hashtbl.find_opt table x with
    | Some y -> y
    | None ->
        let y = f g x in
        Hashtbl.add table x y;
        y
  in
  g
memo_rec hands g, the function with the table, to f as its self. Every call goes through the table.

The three ways to keep a result are one construction: a reference for one value (lazy), a list for each position (fibs), a table for each argument (memo).
